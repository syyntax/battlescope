# Purpose
The app should generate an HTML report based on the uploaded file. The report should output using the light-mode style so that it can be easily printed.

Below is a comprehensive outline for the report generated by the app, based on processing .nessus or Nmap .xml files.

## Report Outline

### 1. **Title Page**
   - Report title (e.g., "Vulnerability Assessment Report - [Scan Name and Date]")
   - Generated date and time
   - Scan source (e.g., "Nessus Results" or "Nmap Results")
   - App version (for traceability)
   - Confidentiality notice (e.g., "For Internal Use Only")

### 2. **Scan Details and Methodology**
   - Scan metadata: Start/end time, duration, scan type (e.g., discovery, vulnerability, or full scan), tools used (Nessus or Nmap), and parameters (e.g., IP range, plugins enabled).
   - Scope: Targets scanned (e.g., IP addresses/ranges, hostnames).
   - Assumptions and limitations: Any exclusions, false positives noted, or incomplete data (e.g., if the scan was interrupted).
   - Data sources: Reference to the input file(s) and any processing notes (e.g., "XML parsed for hosts and CVEs").

#### 3. **Statistical Information**
   - Summary metrics:
     - Total observed systems (hosts/devices).
     - Total vulnerabilities detected.
     - Breakdown by severity (e.g., Critical: 15, High: 20, Medium: 30, Low: 10, Info: 5) – use CVSS scores or Nessus/Nmap severity ratings.
     - Vulnerabilities per host (e.g., average, min/max).
     - Top affected services/ports (e.g., HTTP on port 80: 25 vulnerabilities).
   - Other stats: Open ports count, operating systems detected, or compliance metrics (e.g., number of vulnerabilities matching PCI-DSS requirements).

   *Implementation tip:* Use tables for clarity, and make this section exportable (e.g., to CSV).

### 4. **Graphs and Visualizations**
   - Pie chart: Distribution of vulnerabilities by severity (e.g., colors for Critical/High/Medium/Low).
   - Bar graph: Top 10 vulnerabilities by count or severity (e.g., CVE IDs or plugin names).
   - Heatmap or bubble chart: Vulnerabilities per host, with size/color indicating severity.
   - Line graph: If historical data is available, show vulnerability trends over time.
   - Network topology diagram: Simple visualization of observed systems and their connections (if Nmap data includes topology info).
   - Other ideas: Stacked bar for vulnerabilities by category (e.g., OS, application, network) or a word cloud for common vulnerability keywords.

   *Implementation tip:* Use libraries like Chart.js or D3.js in your web app for interactive graphs. Ensure they're accessible (e.g., with alt text) and exportable (e.g., to PNG/PDF).

### 5. **List of Observed Systems**
   - Table of all hosts/devices detected:
     - Columns: IP address/hostname, MAC address (if available), operating system (inferred from Nmap/Nessus), open ports/services, status (e.g., alive/up), and total vulnerabilities per host.
     - Sortable/filterable if the report is interactive (e.g., in HTML).
   - Grouping: By subnet, OS type, or device type (e.g., servers vs. workstations).
   - Highlights: Flag high-risk hosts (e.g., those with critical vulnerabilities).

### 6. **Detailed Vulnerabilities**
   - Comprehensive list of all vulnerabilities:
     - Grouped by vulnerability ID (e.g., CVE, Nessus plugin ID).
     - For each vulnerability: Description, severity score (e.g., CVSS v3 base score), affected hosts/ports, exploitability (e.g., "Exploit available"), references (e.g., links to CVE database, vendor advisories), and evidence (e.g., scan output snippets).
     - Prioritized: Sorted by severity descending.
   - Categories: Break down by type (e.g., missing patches, misconfigurations, weak encryption).

### 7. **Risk Assessment**
   - Overall risk rating: Calculated based on stats (e.g., using a formula like weighted average of severities).

#### 9. **Recommendations and Remediation**
   - Prioritized action items: For top vulnerabilities, suggest fixes (e.g., "Apply patch KB12345 for CVE-2023-1234").

#### 10. **Appendices**
   - Raw data excerpts: Key sections from the .nessus or Nmap .xml (sanitized for brevity).
   - Glossary: Definitions of terms (e.g., CVSS, CVE).
   - References: Full list of sources, tools, and standards (e.g., NIST, OWASP).
